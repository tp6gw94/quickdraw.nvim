# Implementation Plan: neovim-integration

## Overview

Implement the approved `SPEC-neovim-integration.md` contract: replace the remaining template surface with `require("quickdraw").setup()` and one `:Quickdraw` command, resolve drawing paths from the current Markdown document, edit supported PNG links under the cursor, prompt for new basenames elsewhere, and insert links only after the existing editor session starts successfully.

This phase internally consumes `quickdraw.session.start({ path = absolute_png })` without changing the completed PNG or editor-session contracts. The only public Lua entrypoint remains `require("quickdraw").setup()`.

## Approved Scope

- Optional `setup({ path = "./assets" })`, with `./assets` as the default.
- Relative creation paths resolve from the current Markdown file directory; absolute paths remain absolute.
- One argument-free `:Quickdraw` command.
- Cursor-based editing for the constrained inline Markdown image form generated by the plugin.
- Prompted basename creation, recursive directory creation, and empty-alt insertion at the original cursor byte position.
- Existing Quickdraw PNGs reopen; existing ordinary or invalid PNGs are not overwritten.
- Sanitized notifications, including a copyable local URL when default-browser launch fails.
- Replace template modules, command, tests, README branding, and vimdoc branding.

## Non-goals

- Separate create/edit commands, mappings, completion, file pickers, or multiple editor sessions.
- Full CommonMark parsing, reference images, titles, multiline destinations, remote URLs, queries, or fragments.
- Non-Markdown buffer integration, automatic buffer writes, or automatic Markdown file creation.
- Expanding `~`, environment variables, or glob expressions in configuration.
- Changes to `quickdraw.png`, `quickdraw.session`, the browser UI, or vendored assets unless integration tests reveal a defect.

## Architecture Decisions

### One integration module

Use `lua/quickdraw.lua` for the public `setup()` surface and the command workflow. Keep helpers private and expose only narrow `_test` hooks where a real Neovim boundary cannot be exercised deterministically. Do not introduce separate config, path, or Markdown modules for one consumer.

### Two path representations

Keep the filesystem target and Markdown destination distinct:

- Filesystem target: absolute path passed to `quickdraw.session.start()`.
- Markdown destination: configured or linked path rendered with `/` separators.

Relative values are based on the current document directory. This avoids accidental dependence on global, tab-local, or window-local working directories while preserving the link form the user configured.

### Constrained Markdown scanner

Scan only the current line for inline image ranges and select the range containing Neovim's byte-indexed cursor column. Parse only the form documented in the spec instead of adding a Markdown parser or dependency. Unsupported forms fall back to creation; local PNG candidates retain editor-session validation behavior.

### Boundary validation

Validate configuration once in `setup()`, prompted names before path construction, Markdown destinations before filesystem access, and buffer state before mutation. Reject separators, traversal names, control bytes, whitespace, Markdown delimiters, URI/query/fragment syntax, and non-Markdown buffers at the relevant boundary.

### Asynchronous prompt safety

Capture the originating buffer, window, cursor byte position, document path, and changed tick before invoking `vim.ui.input()`. Before starting or inserting, verify that the original buffer remains valid, loaded, modifiable, and unchanged. This prevents custom asynchronous UI providers from inserting into a stale location.

### Session-first insertion

Create the target directory and call `quickdraw.session.start()` before modifying Markdown. Insert only on session success; browser-launch warnings remain successful sessions and show the URL. If session startup fails, the buffer remains byte-identical.

### Command and errors

Register `:Quickdraw` from `plugin/quickdraw.lua` with `nargs = 0`. The command boundary converts validation/session errors into concise `vim.notify()` messages titled `quickdraw.nvim`; it never logs or exposes the bearer token except that the full URL is intentionally shown for a browser-launch warning.

### Compatibility

Use APIs present in Neovim 0.8: `nvim_create_user_command`, `nvim_win_get_cursor`, `nvim_buf_set_text`, `vim.ui.input`, `vim.notify`, `fnamemodify`, and recursive `mkdir`. Avoid newer-only `vim.fs` helpers.

## Verification Strategy

### Focused automated tests

Use:

```text
nvim --headless --noplugin -u tests/minimal_init.lua -c "PlenaryBustedFile tests/quickdraw/integration_spec.lua"
```

Cover setup replacement semantics, path classification and normalization, constrained Markdown ranges, Unicode byte columns, name validation, prompt cancellation, directory failures, changed-buffer guards, insertion, session errors, browser warnings, and command registration.

### Full local gates

```text
make test
stylua --check lua tests
node --check web/quickdraw/app.js
git diff --check
```

Re-run the vendored manifest check only if vendor files change; this phase should not touch them.

### Manual flow

1. Open a saved Markdown file with default configuration.
2. Run `:Quickdraw` on ordinary text, enter a name, and confirm `./assets/<name>.png` is targeted and the link is inserted at the cursor.
3. Draw and save in the browser; confirm the PNG exists and the Markdown buffer remains user-controlled.
4. Put the cursor anywhere on the inserted image and rerun `:Quickdraw`; confirm editable shapes restore.
5. Change Neovim's working directory and repeat to prove document-relative resolution.
6. Exercise an absolute configured directory.
7. Force browser-launch failure and confirm the URL remains available without unrelated token disclosure.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Cursor byte/character confusion corrupts Unicode lines | High | Use Neovim's byte column directly with Lua byte indices; test Unicode before the cursor |
| Relative paths accidentally follow current working directory | High | Derive from the absolute buffer name only; test `:cd`, `:lcd`, and `:tcd` changes |
| Prompt callback inserts into a changed or different buffer | High | Capture buffer/cursor/changedtick and revalidate before session start and mutation |
| Lightweight Markdown matching accepts ambiguous syntax | Medium | Support only the generated inline subset; test rejected titles, URLs, fragments, whitespace, and nesting |
| Cross-platform absolute-path detection diverges | High | Cover POSIX root, Windows drive, UNC, and slash normalization with pure tests and CI |
| Session starts but insertion unexpectedly fails | Medium | Validate buffer state immediately before start; notify without attempting a compensating file or session mutation |
| Existing ordinary PNG is overwritten | High | Delegate preflight to `quickdraw.session`; never write directly from integration |
| Template cleanup breaks CI/docs | Medium | Remove only after replacement tests pass; run full suite and update docs workflow branding |
